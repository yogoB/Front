# 요고비 리디자인 UX 흐름 확정본 (초안 v0 — 사인오프 필요)

Figma 프레임(랜딩·진입·라이트·디테일·결과)을 읽어 정리한 화면·흐름·백엔드 매핑이다. **이 문서는 아직 확정이 아니다.** 아래 "사인오프가 필요한 결정"을 정하면 구현 스펙으로 승격한다.

기준: 현재 BE 계약([연동 명세](integration.md))과 미지원 목록([현재 상태](state.md)).

## 1. 전체 화면 지도

```
랜딩(마케팅)
  └─ [내 요금제 진단받기] → 진입(모드 선택)
                              ├─ 라이트 모드 ─ ①데이터(범위) → ②통신비(범위) → ③구독 → [분석]
                              └─ 디테일 모드 ─ ①통신사+약정 → ②희망요금(범위) → ③희망구독(유지/해지) → [분석]
                                                                                        │
                        (라이트·디테일 공통) 분석 로딩 → 비교 결과표 → 전환 액션 캘린더
로그인/회원가입: 전 구간 선택. (account.html 기존 화면 재사용)
```

- 라이트 결과의 "더 정확한 절감받기"는 **디테일 모드로 유도**하는 링크다.
- 결과 화면은 라이트·디테일 **동일**하다.

## 2. 화면별 상세 + 백엔드 매핑

범례: ✅ 현재 BE로 됨 · ⚠️ 변환/매핑 필요 · ❌ 현재 BE에 없음(작업 또는 목업 필요)

### S0. 랜딩 (신규)
헤더(로고+로그인), 히어로(헤드라인·CTA·폰목업), 지표 4칸, "이렇게 작동해요" 4스텝, 푸터.
→ **BE 무관.** 정적 마케팅 페이지. 지표 수치(1,200+/50+/₩34,000/96%)는 **고정 문구**인지 실데이터인지 확인 필요.

### S1. 진입 · 모드 선택 (신규)
"데이터사용량·통신비·구독서비스를 분석해서…" + 카드 2개(라이트/디테일).
→ **BE 무관.** 선택에 따라 다른 입력 플로우로 분기.

### 라이트 L1. 데이터 (범위 슬라이더)
"한 달에 데이터 얼마나 쓰세요?" 5~15GB 슬라이더 + "모르겠어요 건너뛸게요".
→ `monthlyDataGb`(정수 필수). **⚠️ 범위→대표 정수 변환 필요. ❌ 건너뛰면 BE 필수값이 빔.**

### 라이트 L2. 통신비 (범위 칩)
"실제로 내는 금액?" 칩(3만↓/3~5만/5~7만/7만↑/직접입력) + 건너뛰기.
→ **⚠️ 통신비는 현재 추천 계산에 미반영(메모).** 입력받아도 절감 기준은 "정가". 실제 반영하려면 BE 변경.

### 라이트 L3. 구독
검색 + 서비스 체크박스 + 등급 드롭다운. 좌측 현재 예상 지출 카드. `분석 시작하기`.
→ `wantedServiceIds` ✅ / 등급 `tierIds`는 `/calculator`용 ✅ / 카탈로그는 `GET /catalog/services` ✅.

### 디테일 D1. 통신사 + 약정
통신사 검색(SKT/KT/LGU+ + **알뜰폰 브랜드: 세븐모바일/M모바일/헬로모바일/스노우맨…**) → "약정 남았나요?" Y/N → Y면 **위약금 경고 + 약정 종료일(date)**.
→ `currentCarrier` ✅(3사) / **⚠️ MVNO 개별 브랜드는 BE enum에 없음**(알뜰폰 하나로 통합 or BE 확장) / 약정여부→`contractType` ⚠️ 부분 / **약정 종료일·위약금 ❌ BE 미계산(메모)**.

### 디테일 D2. 희망 요금
"희망하는 지출요금" 데이터 범위 슬라이더(5~15GB).
→ `monthlyDataGb` ⚠️ 범위 변환. (L1과 동일 이슈)

### 디테일 D3. 희망 구독 (유지/해지)
서비스별 **유지/해지 드롭다운** + `추가하기` 모달(티빙/웨이브/쿠팡/애플TV+/멜론/스포티파이…).
→ `wantedServiceIds` ✅ / **⚠️ "유지/해지" 구분은 BE에 없음**(현재는 "추천 포함" 여부만. 기존에 필수/대체/불필요를 이 이유로 단순화했음).

### R0. 분석 로딩 (공통)
"최적 요금 조합 탐색 중" + 체크리스트(DB조회→결합분석→번들할인→개인화계산→완료).
→ 실제로는 `POST /recommendations` 한 번의 응답 대기. **체크리스트는 연출**(각 단계별 실제 진행 신호는 BE에 없음).

### R1. 비교 결과표 (공통) — **가장 큰 갭**
3열: `현재 상황 ₩82,000` / `추천·최적값 🌟 BEST ₩73,900` / `최저 요금제 기준 ₩94,800→₩73,900`.
행: 요금제/월요금/데이터/**통화/부가혜택/할인·적립/약정기간/위약금**. 상단 `1·6·12개월` 탭. 하단 "왜 나에게 추천됐나".
→ 매핑:
- 추천 목록/총액/절감/출처: `POST /recommendations` ✅ (단, 응답은 결과 N개 리스트지 "현재/추천/최저" 3열 프레이밍이 아님 → **⚠️ 프론트가 재구성**).
- "현재 상황" 금액: 통신비가 메모라 **⚠️ 사용자 입력 기반**.
- **통화/약정기간/위약금 행: ❌** BE breakdown은 항목·금액·출처 구조지 Calls/Contract/Penalty가 아님.
- 부가혜택: `GET /plans/{id}/benefits` ✅ 부분.
- 1/6/12개월 탭: 월 금액 ×6, ×12 표시 ⚠️(단순 표시 곱셈, 금액 "계산" 아님으로 처리).
- "왜 나에게 추천됐나"(AI 설명): **❌** 프론트는 AI 서버 직접 연결 안 함(챗봇 엔드포인트만 존재).

### R2. 전환 액션 캘린더 (공통) — **전면 신규**
현재→전환 금액, 단계별 가이드(준비→가입→구독정리→완료), 월간 캘린더+이벤트, `Google 캘린더 연동`.
→ **❌ 대응 BE API 전무.** 위약금·전환 시점 최적화는 명시적 미지원. Google Calendar 연동은 완전 신규 기능(OAuth·이벤트 생성).

## 3. 매핑 요약 — 무엇이 지금 되나

| 구분 | 지금 BE로 구현 가능 | 변환/재구성으로 가능 | BE 작업 또는 목업 필요 |
|---|---|---|---|
| 화면 | 랜딩, 모드선택, 로딩 연출 | — | — |
| 입력 | 구독 선택·등급, 데이터 정수 | 데이터 범위→정수, 통신사 3사 | 통신비 반영, MVNO 브랜드, 약정 종료일/위약금, 유지·해지 구분 |
| 결과 | 추천 목록·총액·절감·출처·혜택 | 3열 재구성, 6/12개월 표시 | 통화/약정/위약금 행, AI 추천 사유, 전환 캘린더, Google Calendar |

## 4. 사인오프가 필요한 결정

BE 계약을 바꿔야 하는 항목은 **팀/BE에 먼저 제안·승인**이 필요하다(작업 루트 규칙). 아래를 정해야 구현을 시작한다.

1. **범위 입력 변환:** 데이터/통신비 범위를 서버에 어떤 정수로 보낼지 (예: 구간 중앙값? 하한? BE에 범위 필드 신설?).
2. **건너뛰기 처리:** 필수값(데이터, 구독≥1)을 건너뛰면 기본 구간 사용 vs 진행 차단 중 무엇?
3. **통신비:** 입력만 받고 참고 표시 vs 절감 기준으로 실제 반영(→BE 변경)?
4. **MVNO 브랜드:** 알뜰폰 하나로 통합 vs BE에 브랜드 목록 추가?
5. **약정/위약금:** 화면에 표시만(목업) vs 실계산(BE 신규)?
6. **결과 3열 + 통화/약정/위약금 행:** 현재 응답으로 채울 수 있는 것만 실데이터, 나머지는 숨김/목업?
7. **AI 추천 사유:** 범위 제외 vs 챗봇/설명 API 신설?
8. **전환 캘린더 + Google Calendar:** 이번 범위 포함 여부. 포함 시 별도 BE·OAuth 작업 필요.
9. **유지/해지:** 서비스별 구분을 실제로 반영할지(BE엔 현재 없음).
10. **브랜딩:** 헤더가 프레임마다 `YogoB`/`요고비교`로 다름 — 하나로 통일.

## 5. 구현 순서 제안

BE 의존이 없는 것부터 화면을 세우고, 실데이터는 되는 지점부터 연결한다. (화면당 커밋 → sub/sh 푸시 → fly 배포로 확인)

1. 랜딩 → 모드 선택 (BE 무관, 리스크 최소)
2. 라이트 입력 3단계 (범위 변환·건너뛰기 규칙 확정 후)
3. 디테일 입력 3단계
4. 분석 로딩 + 결과표(현재 BE로 채울 수 있는 범위)
5. BE 갭 항목(위약금/캘린더/AI 사유)은 결정에 따라 목업 또는 BE 연동 후
